# Astra 实作体验包

两份可直接使用的繁体中文提示词：替产品或生意做Landing Page，或制作互动3D 扭蛋机，附Codex Goal token 预算设定。

这组提示词搭配〈GPT\-6 Astra 现在做什么比较厉害？模型评测与分析＋Astra 实作体验包〉。选一题，填入自己的内容，让Astra 直接做出能在浏览器开启的作品。

文章拆解了简短需求如何长成一套网站设计，这里让你亲自试一次：交代产品、客群与想达到的效果，把具体设计留给模型。想玩3D，就换成自己的主题与奖品，做一台扭蛋机。

## 包含内容：

- 替你的产品或生意制作Landing Page：填入产品、客群与希望访客采取的行动，产出风格一致、有动态效果和手机版的单页网站。

- 制作互动3D 扭蛋机：自选主题与奖品，完成转把手、掉出扭蛋、打开揭晓，再玩一次的流程。

工具建议：使用支援GPT\-6 Astra、可设定Goal token 预算的Codex 桌面app 一般任务，在各自的空白专案执行。一般codex exec 与临时（ephemeral）对话不适用本包的Goal 前置条件。提示词与回覆都使用繁体中文，两题可独立使用。网页程式不需要另外呼叫付费图片或影片服务。

## 怎么开始

1. 在Codex 建立空白专案，选择GPT\-6 Astra。这两题是在电脑上制作档案，需要能写档、执行程式的环境。

2. 展开下面其中一份提示词，复制后填好【】里的资料；不需要的选填栏位填「由你设计」。

3. 检查「本次Goal token 预算」的数字，再送出。先确认它回报的是系统已建立的Goal 和预算，再让它开始制作。

4. 完成后依开启方式看作品，再用每题下面的三个小测试实际操作。

重要

Goal 是Codex 可持续执行的目标。它的token 预算是达限后收尾的控制，实际用量可能超过设定值。当次回覆与收尾仍会消耗token，所以不要把它当成精准token 硬上限或美元帐单上限。若目前环境没有Goal 工具，提示词会要求先停下说明，改用支援该功能的持续任务再试。功能依据：[Goal 预算栏位](https://learn.chatgpt.com/docs/app-server#manage-a-thread-goal)、[Goal 的停止条件](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)。

## 这次试跑的结果

两题都设定40,000 token 预算，使用GPT\-6 Astra、Medium 思考力度、Codex App Server 0\.153\.4 的持续任务。模型自行载入本机的impeccable 设计skill，以下是这个环境下的两次示例，结果会随专案背景、工具与设定改变。

- Landing Page：以虚构的雾光咖啡月配生意试做，约6 分5 秒产出可开启网站，最终Goal 计数45,658。

- 3D 扭蛋机：以深海研究站和五款虚拟奖品试做，约6 分47 秒产出可玩的CSS 3D 版本，最终Goal 计数58,068。

两次都进入预算达限状态，原执行者尚未完成浏览器实测；我们另用浏览器检查生成档，网站的导览、风味切换与示范表单，以及扭蛋机的抽取、揭晓、再玩、快速连按和手机版都通过。没有修改模型产生的成品程式码。

提示词里的40,000 是本次试跑设定，可自行调整。上面的数字采Goal 计数，不能直接当成API 总token 或费用；这两次结果也不保证每次都能在相同时间内完成。

Prompt 1

### 替你的产品或生意制作Landing Page

功能:做出有完整视觉风格、动态与手机版的产品或生意单页网站。

什么时候用:想为产品、服务或自己的生意做第一版网站，亲自看看Astra 的设计能力。

你会拿到:可在浏览器开启的网站、原始档、操作检查结果与Goal 用量。

可以接到哪:独立使用；不需要先跑另一份提示词。

AI 会问你：

1. 产品或生意提供什么？

2. 主要客人是谁，他们在意什么？

3. 希望访客采取什么行动？资料已填好就直接制作，只补问必要缺漏。

```Markdown
<role>
你是產品網站設計師與前端工程師。請把我的產品或生意做成一個有完整視覺風格、可以在瀏覽器操作的 Landing Page，直接交付作品。
</role>

<context-gathering>
我的產品或生意：【填入產品名稱、提供什麼、特色或價格】
目標客群：【填入主要客人，以及他們在意的事】
希望訪客採取的行動：【例如查看方案、預約諮詢、留下聯絡方式】
品牌或參考資料（選填）：【貼上資料，或填「由你設計」】
本次 Goal token 預算：40000

使用繁體中文。先讀我已填的資訊；若前三項缺漏，集中問一次必要問題，等我補齊。其他可逆的設計選擇由你決定，不要另外要求我先核准一份企劃。
</context-gathering>

<execution>
1. 開工前，使用 Codex 的正式 Goal 功能，為本題設定上述 token 預算；若已有同一題且預算相符的 Goal，先讀取並沿用。回報系統實際記錄的目標、預算與目前用量。若環境沒有此功能或設定失敗，停下說明，不要假裝已限制用量，也不要先開始寫網站。
2. 先把產品、客群與預期行動轉成設計方向。自行選擇適合的配色、字體層級、圖片或程式繪圖、構圖與動態，讓首屏和後面的區塊延續同一套風格。
3. 製作一個完整單頁：清楚有力的首屏、必要的產品或服務介紹、特色或方案，以及呼應預期行動的區塊。動態效果要符合生意與客群，優先確保文字清楚、操作順暢與手機可用。
4. 在目前專案交付原始檔與可開啟的成品。優先使用簡單的前端結構和程式繪圖，避免為這個單頁建立不必要的後端。未提供真實接收服務的表單，只做明確標示的本地示範，不假裝資料已送出。
5. 能實際開瀏覽器時，檢查桌面與手機寬度，操作導覽、主要按鈕和表單，修正影響閱讀或使用的問題。工具不足時，明確列出未實測項目，不把程式碼檢查說成操作測試。
6. 完成核心體驗即可收尾。持續查看 Goal 用量，在接近預算時優先保存可開啟版本與已知問題，不增加範圍、不自行提高預算。達限後停止實質工作並回報現況；未完成就如實標示。
</execution>

<output-format>
用簡短的繁體中文交付：
- 成品位置與開啟方式，讓我立刻看到網站。
- 你採用的設計方向，以及它如何呼應產品和客群。
- 實際測過的操作、未測項目與已知限制，讓我知道現在能用到哪裡。
- 系統可取得的 Goal 預算、實際用量、耗時與停止原因；拿不到的數字標示未取得，不推估美元費用。

<guardrails>

- 不呼叫額外付費的圖片、影片或其他服務，不自行購買素材或部署到外部網站。
- 不讀取或修改此專案之外的私人資料；不啟動其他 agent，以便觀察單次試作。
- 動態提供減少動態的替代呈現，保留基本鍵盤操作與清楚文字。
- token 預算以 Goal 的實際設定為準，不把口頭承諾當成已啟用的限制，也不保證它等於精準美元上限。

```



### 打开后试试看

- 用手机宽度看首屏：产品名称、主要说明和按钮是否清楚可见？

- 点主要按钮：能否到对应区块、连结或明确标示的示范表单？

- 从首屏滑到底：字体、色彩、图片与动态有没有保持同一个风格？

### 制作互动3D 扭蛋机

功能:依主题做出能转动、掉出扭蛋并揭晓奖品的3D 网页玩具。

什么时候用:想用一个小作品测试Astra 的空间、动画和互动能力。

你会拿到:可在浏览器玩的扭蛋机、原始档、操作方式与Goal 用量。

可以接到哪:独立使用；不需要先跑另一份提示词。

AI 会问你：

1. 扭蛋机要用什么主题？

2. 要放哪4–6 个虚拟奖品？

3. 偏好什么风格？资料已填好就直接制作，只补问必要缺漏。

```Markdown
<role>
你是互動 3D 網頁開發者。請做一台有立體感、可以操作的扭蛋機，從轉動把手到掉出扭蛋、打開揭曉結果，讓我在瀏覽器完整玩一輪。
</role>

<context-gathering>
扭蛋機主題：【例如深海研究站、復古玩具店，或填自己的主題】
獎品清單：【填入 4–6 個虛擬獎品名稱】
風格偏好（選填）：【例如溫暖、金屬、透明、可愛，或填「由你設計」】
本次 Goal token 預算：40000

使用繁體中文。若主題或獎品沒填，集中問一次，等我回答；其餘設計細節自行決定。資料足夠就開始製作，不要先讓我審核一套企劃。
</context-gathering>

<execution>
1. 開工前，使用 Codex 的正式 Goal 功能，為本題設定上述 token 預算；若已有同一題且預算相符的 Goal，先讀取並沿用。回報系統實際記錄的目標、預算與目前用量。若功能不存在或設定失敗，停下說明，不要假裝已限制用量，也不要先開始製作。
2. 依主題自行設計機身、透明球艙、扭蛋、把手與出蛋口，讓材質、光線、色彩和介面一致。用 WebGL 或 CSS 3D 等方式做出空間深度，能以拖曳或按鈕切換觀看角度，手機也能操作。
3. 核心流程依序完成：啟動把手 → 球艙有反應 → 一顆扭蛋掉到出蛋口 → 使用者打開 → 顯示從清單中抽到的獎品 → 可以再玩。每次只進行一輪，揭曉前後保持同一個獎品結果。
4. 集中做好一台扭蛋機，不建立帳號、付款、抽獎兌換、排行榜或後端。使用程式生成的幾何和材質，不需要付費素材。
5. 能實際開瀏覽器時，操作完整流程、快速連按、再玩一次、切換角度與手機版。修正重複觸發、結果被覆蓋、動畫卡住或控制無反應等問題。若工具不足，列出未實測項目，不冒稱已測過。
6. 完成可玩的核心體驗即收尾。持續查看 Goal 用量，接近預算時保存可開啟版本與已知問題，不自行提高預算、不擴充功能。達限後停止實質工作並回報現況；未完成就如實標示。

- 實際測過的流程、未測項目與已知限制。
- 系統可取得的 Goal 預算、實際用量、耗時與停止原因；拿不到的數字標示未取得，不推估美元費用。
```

### 玩的时候试试看

- 完整抽一次：把手、掉蛋、打开、揭晓的顺序是否连贯？

- 动画中快速连按：会不会重复掉蛋、卡住，或把奖品改成别的？

- 揭晓后再玩一次，再换到手机：能否正常重来、转动角度和看清楚结果？
